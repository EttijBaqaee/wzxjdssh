# wzxjdssh

以 Docker 部署的 SSH 诱捕服务，支持真实 SSHv2 握手、延迟拒绝认证，以及可选的慢速横幅模式。

默认完成版本交换、密钥交换、服务器签名和加密传输，再让认证请求等待后失败。认证延迟期间由对端主动断开的来源会被标记 1 小时；同一 IP 和客户端标识在冷却期间重连时，提交认证后先进行自适应随机等待，再收到成功消息，随后进入响应随机迟滞的隔离会话，模拟网络时快时慢和偶发停顿。不执行系统命令，也不提供真实 Shell、SFTP 或端口转发。

当前版本：**2.0.4**

镜像：`ghcr.io/ettijbaqaee/wzxjdssh:2.0.4`（Linux amd64），同时提供 `latest` 标签。

## 工作原理

默认 `Mode ssh`：

1. 接收 TCP 连接并发送 SSH 服务端版本标识。
2. 使用持久化主机密钥完成真实 SSHv2 密钥交换和加密传输。
3. 接受密码、公钥探测或 keyboard-interactive 认证流程，按 `Delay` 等待后拒绝认证。
4. 慢速阶段不限总持续时间；新连接到达且容量已满时，按需回收保持最久的慢速连接。

默认每次认证延迟以 **10 秒**为基准并叠加随机扰动，单连接**不限制认证次数**，慢速阶段不限总持续时间。客户端自己的超时或主动断开也会结束连接。

同一 IP 在 60 秒内出现至少两条重叠连接时，所有在线连接优先使用慢速策略，后续认证继续延迟拒绝。该 IP 的旧冷却标记会被清除，这组连接断开时不会再写入认证超时标记。并发策略优先于单客户端冷却；已经进入仿真会话的连接改为基准间隔叠加随机扰动的响应，仍不执行任何命令。

可选 `Mode banner` 在版本交换前持续、缓慢地发送随机可打印字符和 CRLF；首行同样等待 `Delay`。这种模式不完成真实 SSH 握手。

慢速横幅、SSH 延迟认证和仿真网络会话均不限总持续时间，不再因为连接超过 1 小时而退出。即使旧配置中仍有 `MaxConnectionTime 3600000`，慢速阶段也会取消该计时器。只有新的合格连接到达，且总连接数或该 IP 的并发数已满时，才按需回收保持最久的慢速连接；单 IP 满载只回收同 IP 的连接，回收后才接纳新连接。没有新连接时，达到上限本身不会清退。容量回收记录为“容量回收”，不会产生认证超时冷却标记。

客户端主动退出、网络错误、服务停止、未完成握手的超时，以及认证阶段客户端真正空闲，仍可能结束连接；服务端主动拖延不计入客户端空闲时间。自定义的非零认证次数限制也会继续生效，默认不限制次数。

## 功能

- 支持密码、公钥探测、keyboard-interactive；正常连接延迟拒绝，冷却标记匹配的重连仿真登录后持续表现为网络迟滞。
- 保存 Ed25519、ECDSA P-256、RSA 3072 主机密钥，保留数据卷即可在重建后沿用。
- 通过编排环境参数修改宿主机入口端口和 SSH 版本标识。
- 支持总连接数、每 IP 并发、每 IP 速率、握手并发及多种超时限制。
- 严格配置校验；配置重载失败保留旧监听和旧配置。
- 内置 SQLite，记录连接状态、来源、时间、时长、客户端标识和认证尝试，默认保留 90 天。
- 记录用户名、密码、keyboard-interactive 回答，以及客户端提交的公钥正文和 SHA256 指纹；SSH 不传输客户端私钥，公钥探测也不证明持有对应私钥。
- 内置中文 Web UI：统计概览、最近 30 天趋势、来源/用户名/认证方式排行、连接筛选和详情。
- 新增密码 TOP 10、单 IP 最长实际拖延 TOP 10；后者保留已结束连接的实测值，显示每个 IP 的最长单次拖延和累计拖延。
- 连接记录按 IP 汇总，展开后保留每次连接、来源端口与认证详情；主表和展开表均支持最新一页、最旧一页。
- 可选数据库容量上限；超过后按最旧连接清理认证记录并回收 SQLite 文件空间，留空或 0 时不启用容量清理。
- Web UI 管理员密码通过编排设置，支持路径前缀及 HTTP/HTTPS 反代。
- 明亮、暗黑两种主题默认跟随浏览器，可手动切换并记住选择；自动更新开关可暂停每 10 秒刷新。
- 手机连接记录采用卡片布局；管理设置展示当前生效的拖延策略，可保存闲置退出时间（默认 60 分钟，范围 1–1440 分钟）。
- 总览显示拖延中 IP 数（去重）和连接数，提供在线连接拖延时长、单 IP 实时并发 TOP 10。拖延时长累计服务端实际延迟等待，排除握手和客户端等待时间；连接断开后移出实时榜单。
- 支持 JSON 统计、日志级别和优雅退出；认证内容保存在数据库中，不写入标准输出日志。
- 正式镜像基于 scratch，以非 root 用户运行，内置健康检查。

## Docker 部署

配套文件：[compose.release.yaml](compose.release.yaml)、[环境参数示例](.env.example)、[完整编排文档](COMPOSE.zh-CN.md)。

1. 使用 GitHub Container Registry 镜像 `ghcr.io/ettijbaqaee/wzxjdssh:2.0.4`，无需自行构建。
2. 在“容器 → 编排”创建编排，粘贴 `compose.release.yaml`；缺少镜像时会自动拉取。
3. 在编排环境参数区设置至少 12 字节的 `WZXJDSSH_ADMIN_PASSWORD`，其他参数可使用默认值。
4. 启动后确认容器健康状态。从指定端口连接时，应能完成 SSH 握手，认证随后被延迟拒绝。

编排使用 `pull_policy: missing`，固定到 `2.0.4` 版本。离线部署可从 GitHub Release 下载镜像归档并在 1Panel 导入，随后将编排中的 `image` 改为 `wzxjdssh:2.0.4`、`pull_policy` 改为 `never`。也可在 1Panel 构建本仓库的 `Dockerfile`，最终阶段为正式镜像，测试工具不会进入最终镜像。

### 常用编排参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `WZXJDSSH_PORT` | `2222` | 宿主机入口端口；容器内部仍监听 2222 |
| `WZXJDSSH_SERVER_VERSION` | `SSH-2.0-OpenSSH_10.0p2 Debian-7+deb13u4` | 对外发送的 SSH 版本标识，未设置或留空时使用此默认值 |
| `WZXJDSSH_WEB_PORT` | `2223` | Web UI 宿主机端口 |
| `WZXJDSSH_WEB_BIND` | `127.0.0.1` | Web 绑定地址；直接远程访问可设 `0.0.0.0` |
| `WZXJDSSH_ADMIN_USERNAME` | `admin` | 管理员用户名，未填写或留空时使用 admin |
| `WZXJDSSH_ADMIN_PASSWORD` | 必填 | 管理员密码，至少 12 字节 |
| `WZXJDSSH_WEB_BASE_PATH` | 空，使用 `/` | 路径前缀，例如 `/sshpanel` |
| `WZXJDSSH_WEB_SECURE_COOKIE` | `false` | 通过 HTTPS 访问时设置 `true` |
| `WZXJDSSH_RETENTION_DAYS` | `90` | 历史记录保留天数，范围 1–36500 |
| `WZXJDSSH_DATABASE_MAX_MB` | `0`，不启用 | 数据库主文件、WAL、SHM 合计容量，单位 MiB；`1024` 为 1 GiB |
| `WZXJDSSH_MAX_AUTH_TRIES` | `0` | 单连接认证次数上限；0 不限次数，范围 0–1000000 |
| `WZXJDSSH_CONNECTIONS_PER_MINUTE` | `2048` | 每 IP 令牌桶每分钟补充速率及突发容量，0–1000000；0 关闭限制 |
| `WZXJDSSH_MAX_CLIENTS` | `4096` | 总连接上限，1–2147483647 |
| `WZXJDSSH_MAX_CLIENTS_PER_IP` | `64` | 每 IP 并发，0–100000；0 关闭限制 |
| `WZXJDSSH_MAX_PENDING_HANDSHAKES` | `128` | 同时握手上限，1–100000 |
| `WZXJDSSH_DELAY_MS` | `10000` | 每次主动拖延，1–86400000 毫秒 |
| `WZXJDSSH_DELAY_JITTER_PERCENT` | `10` | 普通认证、横幅、并发慢速响应的随机扰动，0–50% |
| `WZXJDSSH_PARALLEL_WINDOW_MS` | `60000` | 同 IP 重叠连接判定窗口，1–3600000 毫秒 |
| `WZXJDSSH_PARALLEL_CONNECTIONS` | `2` | 触发并发慢速策略的重叠连接数，2–100000 |
| `WZXJDSSH_PROBE_FAILURE_THRESHOLD` | `3` | 同 IP 连续握手未完成阈值，1–100000 |
| `WZXJDSSH_PROBE_COOLDOWN_MS` | `900000` | 探针静默冷却，1–86400000 毫秒；期间重连不续期 |
| `WZXJDSSH_SINGLE_AUTH_RETRY_THRESHOLD` | `3` | 连续单次密码拒绝后退出的阈值；0 禁用，范围 0–100000 |
| `WZXJDSSH_SINGLE_AUTH_RETRY_WINDOW_MS` | `900000` | 连续计数窗口，1–86400000 毫秒；按 IP 和完整 SSH 标识区分 |
| `WZXJDSSH_SINGLE_AUTH_RETRY_COOLDOWN_MS` | `3600000` | 触发后的冷却，1–604800000 毫秒；重连不续期 |
| `WZXJDSSH_PARALLEL_COOLDOWN_MS` | `3600000` | 最后一条连接断开后闲置冷却，1–604800000 毫秒；重连重新计时 |
| `WZXJDSSH_HANDSHAKE_TIMEOUT_MS` | `20000` | 握手超时，1–3600000 毫秒 |
| `WZXJDSSH_IDLE_TIMEOUT_MS` | `120000` | 认证空闲超时，1–86400000 毫秒；主动拖延不计入 |
| `WZXJDSSH_WRITE_TIMEOUT_MS` | `5000` | 单次完整写入超时，1–60000 毫秒 |
| `WZXJDSSH_MAX_CONNECTION_TIME_MS` | `0` | 慢速阶段前寿命，0–604800000 毫秒；慢速阶段仍不限时 |
| `WZXJDSSH_MODE` | `ssh` | ssh / banner |
| `WZXJDSSH_MAX_LINE_LENGTH` | `32` | banner 模式行长，3–255 字节，含 CRLF |
| `WZXJDSSH_LOG_LEVEL` | `0` | 0 重要事件，1 连接日志，2 调试 |

例如，发布到宿主机 22，并自定义版本标识：

```dotenv
WZXJDSSH_PORT=22
WZXJDSSH_SERVER_VERSION=SSH-2.0-OpenSSH_9.9
WZXJDSSH_ADMIN_PASSWORD=replace-with-your-own-long-password
```

仅修改端口、保留 Debian 标识：

```dotenv
WZXJDSSH_PORT=22
WZXJDSSH_SERVER_VERSION=
WZXJDSSH_ADMIN_PASSWORD=replace-with-your-own-long-password
```

标识必须是完整的 `SSH-2.0-...` 字符串，可以带发行版注释；不接受换行、控制字符或非 ASCII 字符。这里只改变版本标识，不改变底层 SSH 实现。

策略参数可直接写在服务 `environment:`，或在 1Panel 编排环境参数区设置，由配套 YAML 传入容器。修改后重建容器，并在管理设置查看实际值。在线连接持续时间由服务器计算，避免浏览器时间偏差。趋势图位于统计卡片下方，榜单按认证尝试、拖延统计和来源情况分组，手机单列。

同 IP 并发标记在最后一条连接断开后默认闲置 1 小时冷却，期间重连重新计时；历史连接标签保留。

升级至 2.0.4 时，拉取新镜像并将编排标签改为 `2.0.4`，重建容器，保留数据卷。

同一来源 IP 连续 3 次以 `handshake_incomplete` 结束连接，标记为握手探针，冷却 15 分钟。来源端口不影响累计；完成一次真实 SSH 握手会立即清零，其他结束原因也打断连续计数。按结果完成顺序统计。冷却期间不发送 SSH 横幅或任何 SSH 响应，读取并丢弃数据，到期关闭静默连接；期间重连不延长冷却，重启保留原到期时间。静默连接仍受容量和速率限制，容量不足时关闭新 TCP 连接，不挤掉旧慢速连接。规则仅适用于 SSH 诱捕入口。

## 默认配置

镜像配置路径为 `/etc/wzxjdssh/config`，模板见 [configs/wzxjdssh.conf](configs/wzxjdssh.conf)。时间单位均为毫秒。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `Port` | 2222 | 容器内监听端口 |
| `BindAddress` | 未指定 | 监听通配地址，可设 IP 字面量 |
| `BindFamily` | 0 | 自动选择地址族；4 为 IPv4，6 为 IPv6，双栈行为取决于系统 |
| `Mode` | ssh | ssh / banner |
| `Delay` | 10000 | 认证失败前等待，或 banner 模式行间隔，首行也等待 |
| `MaxLineLength` | 32 | 仅用于 banner 模式，范围 3–255，包含 CRLF |
| `MaxClients` | 4096 | 总接入上限，范围 1–2147483647；实际容量受系统资源限制 |
| `MaxClientsPerIP` | 64 | 每 IP 并发上限；0 关闭此限制 |
| `ConnectionsPerMinute` | 2048 | 每 IP 令牌桶补充速率及突发容量；0 关闭 |
| `MaxPendingHandshakes` | 128 | 同时进行的 SSH 握手上限 |
| `MaxAuthTries` | 0 | 单连接认证失败次数上限；0 不限次数 |
| `ParallelCooldown` | 3600000 | 同 IP 并发标记在最后连接断开后闲置冷却，重连重新计时 |
| `ProbeFailureThreshold` | 3 | 同 IP 连续 handshake_incomplete 触发探针标记的次数 |
| `ProbeCooldown` | 900000 | 探针静默冷却，毫秒；重连不延长 |
| `ParallelWindow` | 60000 | 同 IP 首次并发判定窗口，毫秒；闲置冷却单独设置 |
| `ParallelConnections` | 2 | 窗口内重叠连接达到此数量后，对该 IP 全部连接使用慢速策略 |
| `HandshakeTimeout` | 20000 | 版本交换和密钥交换超时 |
| `IdleTimeout` | 120000 | 认证阶段客户端空闲超时；服务端主动等待不计入 |
| `WriteTimeout` | 5000 | 一次完整写入的超时 |
| `MaxConnectionTime` | 0 | 0 不限时；非零值只约束慢速阶段前的连接，不限制慢速横幅、延迟认证或仿真会话 |
| `HostKeyDirectory` | /data | 主机密钥目录，启动后不能热改 |
| `ServerVersion` | SSH-2.0-OpenSSH_10.0p2 Debian-7+deb13u4 | 配置文件中的默认 SSH 标识 |
| `LogLevel` | 0 | 0 重要事件，1 连接与认证事件，2 调试 |

配置接受空格、Tab 和 `#` 注释。未知键、重复键、非法数值和打不开的显式配置文件均报错。非空策略环境变量覆盖配置文件，未设置或空值沿用文件；配套编排会展开为表中默认值。命令行选项覆盖相应配置与环境变量；`-v` 开启连接日志，`-vv` 开启调试日志。

**标识优先级：**非空 `WZXJDSSH_SERVER_VERSION` 环境变量覆盖配置文件中的 `ServerVersion`。配套编排始终传入该值，留空时展开为 Debian 默认值。若通过挂载配置文件定制了 `ServerVersion`，应将编排参数也设置为同样的值，或移除服务 `environment` 中的这个变量。

## 数据与运维

`hostkeys:/data` 保存主机密钥，`records:/var/lib/wzxjdssh` 保存 SQLite 数据库及其 WAL 文件。升级时编辑原编排、保留同一个项目名和两个数据卷；新建编排通常会生成另一组卷。自定义目录挂载需允许 UID/GID `65532:65532` 读写。

数据库保存对方实际提交的认证内容，请限制管理入口和备份的访问权限。只部署一个实例读写同一数据库目录。备份时先停止编排服务，再备份整个 `records` 卷；运行中备份应使用 SQLite Backup API，不能只复制主数据库而遗漏 WAL。

程序启动及每小时清理过期记录。认证按提交时间过期，已结束连接按开始时间过期；仍在线的连接在结束后清理。删除记录会供 SQLite 重用空间，不保证立即缩小文件或擦除外部快照。Web 总览覆盖当前保留数据，趋势显示最近 30 天，日统计按 UTC，详情时间按浏览器本地时区展示。

容量清理独立于保留天数。设置 `WZXJDSSH_DATABASE_MAX_MB=1024` 后，数据库超过 1 GiB 时按最旧连接开始删除，并把容量降到约 90% 以减少反复清理。已结束连接连同认证内容一起删除；在线连接保留元数据，优先清理其旧认证内容。程序会检查点合并 WAL 并回收空闲页，写入后检查并每秒补查；写入和回收期间可能短暂超过阈值。旧数据库的空闲页如需完整 VACUUM，回收期间需要额外临时磁盘空间。此参数不限制容器日志、备份或主机密钥。

升级前没有保存的拖延时长不会用在线时长代替；历史拖延榜从新版实际记录开始累计。

Web 管理会话默认闲置 1 小时自动退出，可在“管理设置”修改为 1–1440 分钟并持久保存。自动更新不延长会话；退出或容器重启后失效。反代保留路径前缀的 Nginx 示例和升级步骤见 [编排文档](COMPOSE.zh-CN.md)。

| 接口 | 行为 |
| --- | --- |
| `SIGHUP` | 校验并重载配置；更换监听失败时保留旧配置与连接 |
| `SIGUSR1` | 输出 JSON 统计 |
| `SIGTERM` / `SIGINT` | 关闭监听、取消等待并退出 |
| `-check` | 校验配置与版本标识环境参数 |
| `-health` | Web 启用时检查就绪接口与数据库，不生成 SSH 访问记录；关闭 Web 时检查 SSH 监听 |
| `-V` | 输出程序版本 |

已接入连接保留自己的协议模式、超时和认证上限；`Delay` 与 banner 行长可动态更新。通过编排修改端口或环境变量时应重新部署容器。

冷却重连的认证等待默认从 10 秒开始，按来源 IP 和完整客户端 SSH 标识在内存中学习：首次认证中断即按本次实际等待减去一步调整量初始化重连基准；后续等待期间提前退出，基准减少 1 秒；收到认证后的请求或通道时，增加 1 秒，每连接只调整一次。基准范围为 3–15 秒，每次等待叠加约 ±10% 随机扰动，最终实际等待仍限制在 3–15 秒。并发慢速策略优先，服务停止和容量回收不会作为失败样本。学习结果不写入 SQLite，随该标签冷却到期废弃，容器重启后从初始值重新学习；标签本身仍沿用已有持久化机制。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `WZXJDSSH_COOLDOWN_AUTH_DELAY_MS` | `10000` | 冷却重连认证初始等待，需在最小值和最大值之间 |
| `WZXJDSSH_COOLDOWN_AUTH_DELAY_MIN_MS` | `3000` | 实际等待下限，不得小于 3000 毫秒 |
| `WZXJDSSH_COOLDOWN_AUTH_DELAY_MAX_MS` | `15000` | 实际等待上限，不超过 60000 毫秒 |
| `WZXJDSSH_COOLDOWN_AUTH_DELAY_STEP_MS` | `1000` | 每次学习调整量，1–60000 毫秒 |
| `WZXJDSSH_COOLDOWN_AUTH_JITTER_PERCENT` | `10` | 随机扰动比例，0–50；最终仍钳在上下限 |

观测页按认证尝试、拖延统计、来源情况分组；用户名、密码、认证方式相邻，认证榜单同排，拖延与来源分栏；卡片统一固定高度，TOP 10 全部直接显示，不在卡片内滚动，手机单列，间距 12 像素。

普通认证、慢速横幅及并发慢速响应每次按 `Delay` 独立随机等待。`WZXJDSSH_DELAY_JITTER_PERCENT` 默认 `10`，范围 0–50；默认 10 秒基准对应 9–11 秒。仿真网络会话保持独立随机长短响应。超时与冷却截止按原配置计算。冷却重连中断以专用状态和关闭原因记录，不续期。

单次认证重试识别：同一 IP 与完整 SSH 标识在默认 15 分钟内连续 3 次仅提交一次密码、收到拒绝后主动退出，标为“单次认证反复重试”，冷却默认 1 小时。后续重连先自适应随机等待，再进入现有隔离仿真网络会话；不执行命令，不提供系统访问。不同来源端口继续累计，多次认证、公钥探测、认证等待中断、服务停止与容量回收不计入；不符合条件的已完成认证连接打断连续计数。同 IP 并发慢速优先，重连不延长已有冷却。触发前计数仅存内存，冷却标签持久化。

仿真认证成功只表示 SSH 已接受认证，不代表已长期留住客户端。学习增加等待的条件为 shell 或 exec 请求接受后，连接继续保持至少一个 `Delay` 基础周期（默认 10 秒）；仅开通道、发送全局请求或保活不算成功。短暂会话后主动退出会减少后续认证等待，仍遵守 3 秒下限。连接详情记录认证完成时间、认证前耗时、认证后停留、通道和会话请求阶段及底层结束信息；旧记录没有阶段数据时明确显示未采集。阶段事件每连接最多 32 条，只记动作类型与时间，不复制命令或输入正文，跟随连接记录一起清理。

冷却重连若仍在认证等待中断开，将该次真实认证等待减去一步调整量作为新的等待上限，直接下调；适用于升级重启后内存学习重置和低频重连，仍不少于 3 秒，并保持随机扰动。不延长标签冷却，不持久化学习结果，握手时间不混入样本。

首页统计口径：拖延中 IP / 连接统计仍在线且已实际进入拖延流程的来源，等待客户端下一步时仍计入；旁边另列此刻处于延迟响应计时中的数量。握手未完成及探针静默不充作已拖延。认证拒绝按已返回 rejected 的认证尝试计数；接入拦截合计限流等接入拒绝与探针静默，并列出两者。累计实际拖延合计当前保留记录和全部在线连接的实测等待，包含未结束等待，按连接编号去重；并发分别累加，不等于墙上时间，不取 TOP 10 近似值。正常重启保留已结束记录，清理旧记录后其时长也随之移除；旧版未采集及异常中断丢失的等待不推算。
